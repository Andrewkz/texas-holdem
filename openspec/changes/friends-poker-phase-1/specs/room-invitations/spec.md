# Spec Delta

## Purpose

让朋友通过同一游戏站点的邀请链接或四位房间码明确进入目标私人房间，并在移动浏览器分享能力受限时仍能获取可用邀请。邀请只携带公开入场信息，与本人原座位的恢复身份分离，避免误连其他服务器或泄露凭证。

## ADDED Requirements

### Requirement: 生成不包含本人凭证的同站邀请

系统 SHALL 仅在当前房间属于邀请站点配置后端时生成保留站点及路径前缀的邀请链接，仅包含规范化房间码，不包含恢复令牌、昵称、已保存服务器地址、旧查询参数或片段。

#### Scenario: 从含调试参数的页面分享
- **WHEN** 玩家在 `https://example.test/poker/?server=wss://example.test/ws&token=private#old` 为本站后端的房间 AB23 生成邀请
- **THEN** 邀请为 `https://example.test/poker/?room=AB23`，且不会复制调试地址或身份凭证

#### Scenario: 从 IP 站点生成邀请
- **WHEN** 玩家在 HTTP IP 站点生成邀请
- **THEN** 链接保留该站点和有效路径，接收者无需自行拼接房间码或服务器地址

### Requirement: 验证邀请并显示明确入场入口

系统 SHALL 按现有四位房间码字符表规范化邀请参数和手动房间码。有有效邀请且没有可恢复身份时，显示预填目标房间码的昵称入口，只有用户确认加入后才申请座位。

#### Scenario: 小写有效码
- **WHEN** 无对应身份的访客打开包含 `room=ab23` 的链接
- **THEN** 页面显示目标 AB23 的昵称入场入口，不自动建房或发放筹码

#### Scenario: 错误或有歧义的房间参数
- **WHEN** 链接显式包含空码、错误长度、非法字符或多个不同房间码
- **THEN** 页面明确提示邀请无效并允许手动输入，不自动恢复存储中的另一房间

### Requirement: 邀请站点决定目标服务器

系统 MUST 先以邀请站点的部署目标确定连接地址，再匹配本人保存凭证；旧自定义服务器及邀请之外的服务器覆盖参数不得改变邀请目标。无邀请的普通联机入口保留原有地址选择规则。

#### Scenario: 同房间码存在于另一服务器
- **WHEN** 玩家打开本站 AB23 邀请，但存储中是另一服务器 AB23 的令牌
- **THEN** 系统只呈现本站 AB23 的入场入口，不发送该旧令牌，不恢复另一服务器的房间

#### Scenario: 普通联机入口使用开发地址
- **WHEN** 用户通过没有邀请参数的普通联机入口使用有效自定义服务器地址
- **THEN** 该入口继续遵循原有参数、已存地址与默认地址的优先顺序

#### Scenario: 无可移植部署目标
- **WHEN** 当前连接使用自定义后端，且邀请站点没有能指向该后端的部署配置
- **THEN** 系统明确说明无法生成有效邀请，不生成指向另一后端的可分享链接

### Requirement: 浏览器分享能力不足时仍可获取邀请

系统 SHALL 提供邀请分享入口；原生分享或剪贴板不可用、被拒绝或取消时，玩家仍能查看并手动复制完整邀请，失败不得显示为已复制成功。

#### Scenario: HTTP 页面无法使用剪贴板
- **WHEN** 玩家在当前 HTTP IP 站点点击分享或复制，而浏览器不提供相应能力
- **THEN** 页面显示可选择的完整链接及手动复制提示，用户仍可返回牌桌

#### Scenario: 用户取消原生分享
- **WHEN** 用户取消原生分享面板
- **THEN** 原房间状态不变，页面保留邀请入口及文本回退，不自动更换房间

### Requirement: 加入失败保留可理解的返回路径

系统 SHALL 分别呈现房间不存在、房间已满、昵称冲突、网络不可用和协议不兼容的入场结果，并保留修改昵称、重试或返回入口；失败不得偷偷创建新房间。

#### Scenario: 房间已满
- **WHEN** 第七名访客确认加入六人已满的房间
- **THEN** 页面提示房间已满，访客不获得座位、不进入旁观模式，也不改变已有玩家状态

#### Scenario: 邀请房间不存在
- **WHEN** 访客确认加入已被清理或不存在的房间码
- **THEN** 页面说明无法加入并提供返回入口，不自动创建同名房间
