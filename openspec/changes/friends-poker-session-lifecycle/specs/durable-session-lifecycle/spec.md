# Spec Delta

## Purpose

让好友本场的结束、离开、全部断线和服务器重启具有一致、可追溯的结果。完整手的筹码与账本作为原子检查点保存，未完成手不被部分计入结果，恢复后保留已确认的参与者及管理意图并明确说明回退。

## ADDED Requirements

### Requirement: 房主只能在完整手边界结束本场
系统 SHALL 允许在线有效房主在大厅直接结束，或在当前手进行中申请该手结算后结束；当前主池、边池和离座权益照常处理，之后不再发下一手。非房主、旧连接和重复请求不能重复结束。

#### Scenario: 各下注轮请求结束
- **WHEN** 房主在翻牌前、翻牌圈、转牌或河牌请求结束
- **THEN** 显示本手结束后结束，本手正常结算，只生成一个最终结果，不再发下一手

#### Scenario: 大厅结束与权限拒绝
- **WHEN** 房主在大厅请求结束，或非房主、失效旧连接请求结束
- **THEN** 有效房主可直接结束；无权限者请求被拒绝且不改变生命周期

### Requirement: 最后主动离开仍完整结清本手
系统 MUST 区分主动离开和临时断线；最后有效参与者明确离开时进入结束流程，继续按规则处理尚未完成的自动行动及全压权益，结清后结束，不直接以空房删除账本或在途底池。

#### Scenario: 最后一人手中离开
- **WHEN** 最后一名在座者明确离开而当前手尚有权益
- **THEN** 清理当前手并结清所有历史参与者的权益，形成固定结算，不再开新手

### Requirement: 房主移交仅选有效在线座位
系统 SHALL 保留在线优先接任；无在线候选时保留待接任，由等待期内首位有效恢复者接任。短暂断线不主动移交，旧连接不能夺回权限。

#### Scenario: 在线与待接任路径
- **WHEN** 房主主动离开，分别存在在线候选或仅有离线保座者
- **THEN** 前者移交在线者；后者等待首位有效恢复者，新访客不能在保座期内抢占待接任

#### Scenario: 房主短暂断线
- **WHEN** 房主仅断线后在有效期限内恢复
- **THEN** 仍恢复原房主身份，旧连接迟到回调不清除新连接或改变权限

### Requirement: 全员断线保留独立三分钟等待
系统 MUST 在服务端识别最后在线座位断开时持久记录180秒绝对截止时间，期间不发新手。单人保座移除、重复关闭、刷新和重启不能延长或提前终止此期限；有效恢复取消旧等待，下一次全断线才建立新期限。

#### Scenario: 全断线等待内恢复
- **WHEN** 全员断线后在179999毫秒时有效恢复
- **THEN** 本场继续且旧到期回调失效，身份、账本和已结清余额不重建

#### Scenario: 准确边界到期
- **WHEN** 到达180000毫秒仍无恢复，即使回调延迟执行
- **THEN** 按固定期限结束，迟到恢复得到结束结果而不重新开启本场

#### Scenario: 等待跨重启
- **WHEN** 进程在全断线等待期间被终止并重启
- **THEN** 原绝对截止时间保持不变，已过期时在启动恢复阶段立即处理，不重新获得三分钟

### Requirement: 全断线到期对未完成手采用检查点回退
系统 SHALL 在全断线截止且仍有未完成手时回到最近完整结算，再按保留的管理意图完成归属与结束；显示该手已回退，不伪造赢家或保留部分临时输赢。若该手已完整提交则保留该新检查点。

#### Scenario: 超时期间尚有未提交手
- **WHEN** 全断线期限到期且当前手尚未完整结算
- **THEN** 丢弃该手临时筹码变化，按最近完整检查点统一结束，最终净盈亏仍合计为零

### Requirement: 检查点与账本作为一致结果持久提交
系统 MUST 将完整手筹码、累计投入、补码次数、离开归属、庄位、单调手号、管理回执和检查点版本作为一致结果提交。成功确认或下一手开始必须在提交之后；崩溃恢复只能得到提交前或后的完整结果，不能重复派奖、补码或归属。

#### Scenario: 检查点提交前后进程强杀
- **WHEN** 在完整手提交前、写入中、提交后确认前强制终止独立服务进程
- **THEN** 同目录重启后恢复对应旧或新完整版本，已确认提交必须恢复新版本，无半提交及重复派奖

#### Scenario: 补码离开和结束提交进程强杀
- **WHEN** 在补码生效、离场清算、重入扣回或结束提交的写入/确认边界强杀真实进程
- **THEN** 筹码、投入、归属和回执保持一致，原请求重试仅返回一次结果，最终快照和结束时间不重复生成

### Requirement: 重启只回退未完成手且保留已确认控制意图
系统 MUST 在启动接受连接之前加载并验证持久记录；未完成手退回最近完整手检查点，已提交的加入身份、补码请求、离座、结束意图与期限仍保留。不能恢复旧私牌或静默新建丢失/损坏本场。

#### Scenario: 第二手不同轮次强杀
- **WHEN** 已完成至少一手后在下一手不同下注轮强杀并重启
- **THEN** 回到最近完整结算，客户端清除旧牌和动作并显示回退说明，已确认管理操作不丢失

#### Scenario: 持久记录损坏
- **WHEN** 启动读取到不合法或不完整的已提交记录
- **THEN** 明确报错并停止提供错误恢复，不忽略记录新发5000或伪造结算

### Requirement: 过期牌局动作不能跨恢复生效
系统 MUST 用本场、当前运行代号和手号确认行动归属；最新权威恢复/回退状态应用前不允许行动，旧连接、旧动画、旧排队快照或旧手行动不得覆盖恢复结果。管理命令可按原请求查询，出牌不自动重放。

#### Scenario: 相同手号不同恢复代号
- **WHEN** 旧页面或动画晚于回退后新状态完成
- **THEN** 新状态保持，旧动作被服务端拒绝，不重复牌张、赢家或权限
