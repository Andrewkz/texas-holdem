# Spec Delta

## Purpose

为一场好友虚拟筹码牌局保留可验证的参与者身份、首次投入、爆零补码与离开后的筹码归属，使刷新、重入与重复请求都不产生额外筹码，并在整场结束时包含所有曾参与者、独立核对净盈亏总和为零。

## ADDED Requirements

### Requirement: 本场身份独立于座位和房间码
系统 MUST 为本场和参与者提供稳定身份，恢复须验证本场证明而非昵称。房间码复用不得混淆场次；同身份刷新、重连、接管或离开后重入不得重复生成参与者或首次5000投入。

#### Scenario: 同身份跨连接恢复
- **WHEN** 玩家刷新、断网恢复或新标签页接管
- **THEN** 本场与参与者ID保持不变，首次投入仅一次，不新增5000，旧连接不能继续操作

#### Scenario: 主动离座后按原身份重入
- **WHEN** 已离座者明确使用该场有效证明重入且有空位
- **THEN** 沿用原参与者、累计投入和余额，不以昵称新建身份；主动离座保留可供明确重入的证明但不自动重占座位

#### Scenario: 同码不同场或同昵称无证明
- **WHEN** 房间码被复用或访客只有已有玩家昵称
- **THEN** 不恢复原身份，不向新场发送旧证明；无效证明给出明确结果而不静默新入座

### Requirement: 爆零补码仅在下一手生效一次
系统 SHALL 只允许已结清余额为零的在座玩家主动确认免费补至5000，不接受任意金额。接受后显示待生效，在下一手发牌前一次性增加5000筹码、累计投入和一次补码次数；不改变当前手的底池或权益。

#### Scenario: 合格玩家确认补码
- **WHEN** 完整手结算后玩家余额为零并确认补码
- **THEN** 请求先呈现待生效，下一手发牌前得到5000，累计投入增加5000且补码次数仅加一

#### Scenario: 全压不等于爆零
- **WHEN** 玩家当前全压余额为零但本手权益尚未结清，或玩家仍有已结清余额
- **THEN** 补码被拒绝，不改变底池、筹码、账本或补码次数

#### Scenario: 重复或竞态补码
- **WHEN** 同一请求重试、丢失确认后重试，或另一个请求试图重复待生效补码
- **THEN** 同一请求得到原结果，同一爆零周期最多生效一次；换请求ID不能重复领取

#### Scenario: 补码尚未生效便离座
- **WHEN** 已接受待补码但玩家在下一手之前明确离座或本场结束
- **THEN** 不凭空发放补码，待请求得到明确取消或不生效结果，投入不增加

### Requirement: 离开本手保留已投入权益
系统 MUST 先按规则处理本手权益再确定离开归属。非全压离开者自动弃牌，全压离开者保留主池及边池资格；待结清者不能显示最终余额，最后一人离开不能直接删除未完成权益。

#### Scenario: 普通离座和全压离座
- **WHEN** 普通玩家或全压玩家在手中离座
- **THEN** 普通玩家按自动弃牌流程处理，全压玩家仍可获主池或边池；只在完整结算后确定归属

#### Scenario: 主池边池和平分
- **WHEN** 离座全压者分别赢主池、赢边池或平分底池，并存在未匹配下注返还
- **THEN** 归属与原引擎裁决一致，未匹配筹码不消失、不计两次

#### Scenario: 未结清便要求重入
- **WHEN** 已离座者本手权益尚未结清便明确重入
- **THEN** 显示待本手结清，不提前带回暂估余额、不撤销已发生弃牌；结清后可按原身份重入

### Requirement: 离场归属与重入余额只计一次
系统 SHALL 在离座结清时将余额转为已离场归属，在同身份重入时将同一余额从已离场归属扣回在场余额；不新增首次投入。账本持续保留历史离开者和事件，座位上限六人不限制历史参与者记录。

#### Scenario: 反复离开与重入
- **WHEN** 同一参与者多次离开并按原身份重入
- **THEN** 每笔筹码只处于已离场或在场一处，历史投入不增加，事件可追溯且不重复

#### Scenario: 超过六名历史参与者
- **WHEN** 六座中有人离开后新访客入座
- **THEN** 同时入座仍不超过六，账本和最终结算仍包含被替换的参与者

### Requirement: 管理操作具有持久幂等结果
系统 MUST 对补码、重入、主动离座及结束请求保留本场、参与者、操作类型和请求ID关联的结果。成功必须在一致持久提交后确认；重复相同请求返回原结果，同ID不同内容拒绝，超时呈现结果待确认，不换ID重复执行。

#### Scenario: 提交成功后确认丢失
- **WHEN** 操作已提交但客户端未收到确认并使用原请求ID重试或查询
- **THEN** 返回同一结果，不重复筹码变更或事件

#### Scenario: 持久提交失败
- **WHEN** 保存账本、回执或筹码时失败
- **THEN** 不返回成功、不显示半提交余额，停止继续发新手并给出可理解的错误

### Requirement: 最终净盈亏可独立核对为零
系统 MUST 以累计投入I和最终归属F计算净盈亏P=F−I；F为已结清离场净归属加结束持有余额，包含全部曾参与者。未结清权益不能冒充最终数字，全部最终P合计为零。

#### Scenario: 多手多次补码和离开者
- **WHEN** 包含多次补码者、离开者和重入者的本场结束
- **THEN** 每行投入、补码次数、最终归属与事件一致，全体净盈亏合计为零，可由独立手算验证
