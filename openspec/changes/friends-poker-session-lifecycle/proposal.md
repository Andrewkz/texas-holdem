# Proposal

## Why

第一阶段已完成并发布邀请、会话恢复与浏览器交互，但整场身份、筹码归属和未完成手仍只在内存中，离座后无法核对完整盈亏。用户已要求继续完成原路线图全部剩余阶段，本变更按阶段2→3→4交付整场账本、可靠结束与恢复、30天只读结算分享。

## What Changes

- 稳定本场ID与参与者身份独立于房间码、座位和连接；离座保留本场证明，明确操作后可按原身份重入，不重复发放首次5000。
- 记录首次投入、补码、完整手结算、离场归属和重入扣回，保留已离开者；待结清权益不显示为最终余额，最终净盈亏合计为零。
- 爆零玩家主动确认免费补至5000，下一手生效；重试、重复请求、全压但尚未结算均不能多领筹码。
- 房主可直接结束大厅或申请本手结束后结束；最后主动离开继续完成当前权益，全员仅断线则等待180秒、期间不启动新手。
- 完整手检查点、持久控制意图与账本原子保存；进程中断回到最近完整结算，保留已提交加入/补码/离开/结束意图并显示回退说明。全员断线到期的未完成手采用相同回退规则后结束。
- 整场结束形成固定结算，包含离开者；不可猜测的只读分享自结束时起30天有效，访问/复制不续期，页面/API不返回身份凭证或私牌。
- **BREAKING**：协议v3增加稳定本场身份、幂等管理命令、账本/结束/回退状态和防过期行动契约；客户端与服务端配套交付。
- 保留2–6真人、虚拟筹码、固定20/40及单机AI；沿用用户批准的实际编译包浏览器验收。增加真实独立进程SIGKILL故障测试，不用内存测试替代崩溃一致性。

## Capabilities

### New Capabilities

- `session-chip-ledger`：本场参与者、初始投入/补码、离场与重入归属、幂等及零和核对。
- `durable-session-lifecycle`：按手结束、断线等待、完整手检查点、持久提交与重启回退。
- `settlement-sharing`：固定整场结算、30天只读分享、隐私投影及浏览器完整流程。

### Modified Capabilities

无正式主规格可修改；`openspec/specs/` 当前为空。继承并回归 `friends-poker-phase-1` 变更中的邀请、个体化权限、恢复与手机交互，不将该阶段的内存限制作为后续交付结果。

## Impact

- 服务端：新增纯账本聚合、原子文件存储、恢复与只读HTTP服务；调整Room/RoomManager/index，部署配置增加独立可写持久化目录与结算API代理。
- 客户端：扩展protocol、凭证、OnlineSession与入口状态；增加账本、补码、结束/回退反馈及独立只读结算入口，assets新增源码配套.meta。
- 验证：按三个阶段完成自动测试、真实WebSocket/HTTP、真实子进程崩溃和2/6独立浏览器全链路；生成实际Cocos构建与逐项验收记录。
- 不增加账号、资金交易、任意金额补码、盲注自定义、匹配、观战、排行榜或多进程服务。生产发布依照届时该版本授权，开发不操作线上房间。
