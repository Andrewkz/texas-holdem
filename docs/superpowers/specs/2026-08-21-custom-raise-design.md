# 自定义加注金额设计

## 目标

让玩家在轮到自己且允许加注时，选择合法的任意加注总额，而不仅限于当前的最小加注。

## 交互

1. 原操作栏的“加注至 N”按钮改为“自定义加注”。
2. 点击后展开一个加注面板，显示当前选择的“加注至 N”。
3. 面板同时提供三种金额选择方式：
   - 直接输入总下注额；
   - `−20` 与 `+20` 步进调整；
   - 最小加注、半池、满池、全压四个快捷档位。
4. 点击“确认加注”才调用规则引擎；点击“取消”收起面板且不改变牌局。

## 金额规则

- 金额语义为本轮下注后的总额（与现有 `{ type: 'raise', to }` 一致），不是额外投入额。
- 最小值是引擎给出的最小合法加注额；最大值是当前玩家本轮已下注金额加剩余筹码。
- 输入或快捷计算得到的金额会被夹取到该区间内，并按 20 筹码单位向下对齐；若上限低于 20 的倍数，保留全压金额。
- 半池和满池以面板打开时的底池为基准，分别在跟注额基础上加上 `pot / 2` 与 `pot`，再应用上述合法范围和步长规则。
- 如果没有合法的常规加注动作，操作栏不显示自定义加注入口；全压继续作为独立操作。

## 组件边界

- `PokerEngine` 继续是唯一的规则裁决者，现有 `raise.to` 的合法性校验不放宽。
- 新的金额规范化函数为纯函数，接收最小值、最大值、底池、跟注额和候选金额，便于单元测试。
- `GameBootstrap` 仅负责显示面板、收集输入、调用规范化函数并在确认时发送合法 `{ type: 'raise', to }`。

## 验证

- 单元测试：步进、直接输入、半池、满池、全压上限及不足最小加注的规范化结果。
- 引擎测试：一个高于最小值但不超过可用筹码的自定义 `raise.to` 可被接受。
- Cocos 预览：面板打开/取消、快捷档位、确认后筹码与底池变化，以及无效输入不会推进牌局。
