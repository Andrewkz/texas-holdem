# 好友德州扑克产品规格与实施路线图

## 1. 产品目标与范围

让 2–6 位朋友在手机浏览器中通过邀请进入私人牌桌，持续完成多手德州扑克，并在整场结束后查看、分享可核对的虚拟筹码结算。首次加入、刷新、临时断线、主动离开和服务器重启，都应有清楚且一致的处理结果。

本文件整理已确认的产品决定，不代表功能已经交付。后续技术设计需要细化身份恢复、事件去重、存储事务和页面状态，但这些细化不得擅自扩大产品承诺。规划本身不触发开发、构建或部署。

### 已确认的产品决定

1. 只使用虚拟筹码，无充值、提现或真实资金交易。
2. 联机模式为 2–6 名真人的好友私房，不使用 AI 补位；原有单机 AI 模式保留。
3. 不做账号注册与登录，仍以游客方式参与；恢复座位需要可验证的会话身份，昵称不能作为身份凭证。
4. 盲注固定为 20 / 40，本轮不增加自定义盲注。
5. 首次加入本场获得 5,000 筹码；同一身份刷新、断线恢复或重入本场不能被误记成首次加入，也不能重复发放首次筹码。
6. 支持好友邀请链接和房间码；手机打开邀请后应进入对应房间的加入或恢复流程。
7. 手机浏览器横屏优先，同时兼容电脑；竖屏提示横屏体验。完成邀请、输入昵称、行动、重连和查看结算的核心路径应可在手机上操作。
8. 牌局进行中可以加入房间；新玩家等待下一手发牌，不能中途领取当前手牌或参与当前底池。满 6 人时提示房间已满，不提供旁观入口。
9. 刷新与临时断线后应恢复本人座位、筹码和可见状态，断线保留座位 3 分钟；期间行动超时仍为 30 秒，能过牌则过牌，否则弃牌。恢复不重置本次行动计时，不能创建重复玩家，也不能显示其他玩家的私有手牌。
10. 需要整场筹码账本，记录首次投入、后续补充、离开时归属筹码及最终盈亏；“投入”只是虚拟筹码统计术语。
11. 玩家爆零后可以免费补至 5,000，从下一手生效；每次补充都计入本场累计投入，不能通过重试重复记账。
12. 房主可以结束本场；有未完成手牌时，在该手结算完成后结束，不截断底池或边池权益。
13. 房主主动离开时，将房主权限移交给仍在线的玩家；没有在线接任者时，在 3 分钟等待期内由首位恢复连接的玩家接任，不随机指定离线房主。
14. 最后一位参与者明确主动离开时结束本场；所有人只是断线时保留本场等待 3 分钟，两者必须区分。有人在等待期内恢复时，应恢复本场而非创建新场。
15. 持久化以完整一手结算后的检查点为准。服务器在一手进行中重启时，丢弃该手未提交结果，回到最近完整检查点，并向玩家说明回退。
16. 整场结束后可分享只读结算；分享有效期从本场结束时起计算，为 30 天，不能因重复访问或重新复制链接延期。
17. 结算包括已离开玩家；处理完所有未完成手牌权益后，全体玩家最终净盈亏之和必须为零。
18. 本轮不做公开随机匹配、独立观战、排行榜；不把中途加入等待下一手扩展为观战产品。

## 2. 当前基线与差距

当前基线以现有代码行为为准，不能用旧设计文档中的计划代替实际交付。

| 方面 | 当前基线 | 本路线图要完成的能力 |
| --- | --- | --- |
| 联机规则 | 服务端权威裁决，2–6 人、初始 5,000、固定 20 / 40、房间码加入；保留单机模式 | 保持既有规则，补齐好友整场流程 |
| 断线 | 现有客户端会话可携令牌重试连接，服务端默认保留座位 60 秒 | 明确单人断线恢复及全员断线等待 3 分钟的状态转换 |
| 页面刷新 | 凭证保存在本机；重新加载不会自动恢复上一在线会话，只会在联机表单中预填部分信息 | 启动时识别可恢复身份，进入恢复流程 |
| 状态存储 | 房间与进行中牌局只在服务端内存中；进程重启会丢失，房间码也不是不可复用的本场 ID | 手间检查点、恢复身份、账本与结束状态持久化 |
| 显示与交互 | 1280 × 720 固定设计画布，浏览器外壳按 16:9 缩放；已有按钮反馈、弹层与表单基础交互 | 手机核心操作可读可点，邀请和恢复过程有明确反馈 |
| 中途加入 | 已有进行中加入与下手参与的基础逻辑，尚需完整手机流程与边界验收 | 等待状态、重新进入、跨手同步形成闭环 |
| 整场结算 | 有每手底池结算，无覆盖离开、补充和恢复的整场账本 | 可核对的整场盈亏与 30 天结算分享 |

当前的 60 秒座位窗口不等于计划中的全员断线 3 分钟等待，也不等于服务器重启恢复。固定画布能缩放不等于已完成手机体验验收。

## 3. 关键流程与一致性要求

### 邀请、加入与恢复

朋友打开邀请链接，看到房间信息并输入昵称后加入。若本机已有该场的有效身份，应优先进入恢复流程。恢复成功后直接展示大厅或当前牌桌；本场结束后的结算入口待里程碑 3、4 完成后提供，不在早期阶段假设它已存在。不应先创建新玩家再合并。房间不存在、已结束、已满或凭证失效时给出可理解的结果，允许回到加入入口。

有效邀请的目标服务器由邀请站点的部署配置/同源地址确定，不能让本机旧的自定义服务器记录把邀请导向另一服务器；普通无邀请入口可保留现有地址选择规则。邀请信息与本人重连凭证必须分离，不能把房主或发送邀请者的令牌拼入邀请链接。恢复身份绑定到对应服务器及稳定本场身份；邀请指向不同服务器时，不可把已有凭证发送过去或恢复到另一场。房间码可能被复用，不能只凭同一个四位码判定它仍是原场。

页面应区分“正在连接”“正在恢复”“等待下一手”“轮到你行动”“连接已失效”，不能让玩家把连接等待误认为操作没有生效。重连期间不得重复提交上一动作；新连接接管同一身份后，旧连接不能继续操作该座位。

### 筹码账本、离开与补充

对每位本场参与者维护稳定的内部身份；座位与连接可以变化，账本归属不能变化。首次投入只发生一次；免费补充只在符合爆零条件时发生，并在下一手开始前生效。断线重试、刷新、重复请求和同身份重入均不能额外增加投入或筹码。

对玩家 `i`，定义累计投入 `Iᵢ` 为首次 5,000 与所有已生效补充之和；最终归属筹码 `Fᵢ` 为累计已结清离场余额减去同身份重入时带回的余额，再加结束时仍持有的余额。同一笔筹码在“已离场归属”与“当前持有”之间只能计一次；重入返还不算新的首次投入或补码。最终净盈亏 `Pᵢ = Fᵢ − Iᵢ`。整场完成结算后，所有曾参与玩家满足 `ΣPᵢ = 0`。

玩家在一手中离开时，不能用退出瞬间的显示筹码草率终结账本：应先按既有牌局规则处理其已投入筹码、自动行动及全压/边池权益，待该手结算后确定最终归属。离开者记录仍保留在本场结算中。恢复相同身份时沿用已有记录；昵称相同不构成身份恢复依据。

补充的按钮位置、请求确认方式、账本事件字段，以及暂存离开权益的实现方式，属于实施细化。建议玩家主动确认补码，在里程碑 2 的详细交互设计中落实；这不是额外已批准的功能承诺。不得借此新增付费、任意金额补码或中途改动底池等功能。

### 结束、断线与重启

- 房主请求结束：未开手时可直接完成本场结算；已有手牌时标记“本手结束后结束”，禁止再自动发下一手，当前手仍按规则完成。
- 房主主动离开：有其他在线玩家时转移权限；无在线候选者时等待首位玩家在 3 分钟内恢复后接任，不随机指定离线房主。离开本身不等于结束其余人的本场。
- 最后一位参与者明确主动离开：结束本场，仍须完整处理当前手及归属权益，不能遗失账本。
- 全部参与者断线：进入 3 分钟等待，不能当作全员主动离开；期间不启动新的手牌。等待到期仍无人恢复时，完成本场的结束与结算流程。
- 服务器中断：恢复最近完整手的检查点；不把未完成一手的临时筹码变动计入已提交账本。恢复页明确说明该手已回退，不能伪装为从原牌面继续。

计时器如何在服务端重新加载、自动行动与结束状态如何串行化、最后一人离开和结束请求竞态如何去重，需在实现设计中落实。全员断线到期时若仍有未完成手牌，结束结算与检查点回退必须采用一致规则，不得为凑出最终数字伪造牌面或输赢；具体状态转换在里程碑 3 的技术方案中定义和验证。验收关注上述产品结果，不预先承诺特定数据库或事件框架。

## 4. 最小持久化与分享边界

持久化的最小模型应能表达以下信息，字段名和具体存储技术可在实施阶段选择：

| 数据 | 最少需要保留的内容 | 需要保证的结果 |
| --- | --- | --- |
| 本场 | 稳定本场 ID、房间码关联、阶段、房主、创建/结束时间、结束原因、结束待执行标记 | 房间码不能混淆不同场次，重启后不会误发下一手 |
| 参与者 | 稳定参与者 ID、昵称、座位/参与状态、可恢复身份凭证的安全校验信息 | 同人恢复不生成重复玩家或首次投入 |
| 账本 | 稳定事件 ID、参与者、本场、事件类型、金额、补码次数、生效手号或检查点版本 | 首次投入、补充与离开归属可去重、可核对 |
| 完整手检查点 | 已提交手号/版本、各玩家结算后筹码、累计投入、离开归属、庄位及开始下一手所需状态 | 重启可从手间边界恢复；未完成手不会部分提交 |
| 生命周期期限 | 全员断线等待的截止时间、恢复所需状态 | 重启不无条件重置 3 分钟等待 |
| 最终结算与分享 | 固定结算快照、分享标识、本场结束时间和失效时间 | 结算不可被后续场次改写，满 30 天失效 |

每手结算后的筹码、账本变动和检查点版本必须作为一致结果提交；进程中断后只能看到提交前或提交后的完整状态。补充、离开及结束操作也需有明确的提交边界和重复请求处理，避免“筹码已加但账本未记”等分裂结果。

分享只展示该场的参与者昵称、补码次数、累计虚拟投入、最终归属筹码和净盈亏等结算信息，使用不可猜测的只读分享标识。分享页面和接口不得返回重连令牌、连接凭证、私有手牌或未公开牌面；分享链接不能用于入座、恢复身份或出牌。有效期为 `结束时间 + 30 天`，到期展示失效状态并拒绝继续读取结算内容。清理任务、索引和备份保留策略属于存储实施细化，不能把公开可读有效期延长。

## 5. 四个里程碑

没有必须上线的日期，不据此推定无限预算或开发投入；按依赖关系与验收门槛推进。每个里程碑完成后都应明确交付能力、已知限制和验证证据，再决定后续实施。

### 里程碑 1：手机邀请与会话恢复顺畅

**交付范围**：手机邀请链接、房间码加入、启动时自动恢复有效身份、进行中加入后等待下一手、单人断线反馈与重连、移动端关键操作优化。梳理全员断线等待状态，为后续持久化阶段留出明确边界。

**验收门槛**：

- 两部手机或独立浏览器身份通过同一邀请进入同一房间，房主可开始游戏。
- 刷新后自动恢复本人座位；昵称、筹码、可见手牌和当前操作权限一致，无重复玩家或额外首次筹码。
- 当前手进行中加入的玩家清楚看到等待状态，只从下一手开始获得手牌和行动权；其他人继续行动时，每次更新仍保持等待且无合法动作。
- 断网再恢复后状态与服务端一致，等待期间有反馈；失效凭证有明确退出结果。用假时钟覆盖 180 秒座位保留边界和独立的 30 秒行动计时，实际手机验证刷新、切后台和断网恢复。
- 手机核心流程无关键文字遮挡、按钮重叠或必须缩放页面才能点击的操作；固定画布缩放方案是否足够以实测为准。

**阶段限制**：这是连接和移动体验的早期增量。里程碑 3 之前服务端不承诺持久留存；尚不能宣传重启恢复、完整账本或可靠整场结算分享，也不提供尚未完成的最终结算结果。全员断线 3 分钟与检查点跨重启恢复在里程碑 3 完成整体验收，不能将其描述为当前已有的 3 分钟宽限期。

### 里程碑 2：整场账本与爆零免费补充

**交付范围**：稳定本场/参与者身份、首次投入与离开归属记账、补码次数、累计投入与净盈亏展示、爆零免费补至 5,000 且下一手生效、同身份恢复和重入去重。

**验收门槛**：

- 首次加入只记一次 5,000；刷新、重连和同身份重入不会增加初始筹码或重复账本事件。
- 爆零后补充生效一次，下一手从 5,000 开始，累计投入增加 5,000；重复请求不能重复补充。
- 有余额玩家不能通过爆零入口获取额外筹码；当前手的底池、筹码和边池不被补充流程改写。
- 中途离开、离开后同身份重入、全压后离开及边池场景均保留正确权益和账本归属。
- 用包含离开者与多次补充者的完整测试场验证 `ΣPᵢ = 0`；未结清权益在界面中不能显示为最终数值。

**阶段限制**：这是账本能力的早期增量。通过内存场景记账测试不代表通过进程崩溃一致性测试；最终持久化、回退语义与结束流程仍需里程碑 3 验收。

### 里程碑 3：按手结束、检查点与重启恢复

**交付范围**：房主本手结束后结束本场、主动离开转移在线房主、最后主动离开与全员断线的不同处理、全员断线等待 3 分钟、完整手检查点、服务器重启回到最近完整结算。

**验收门槛**：

- 房主在任意下注轮请求结束，当前手正常结算，所有权益落账后只结束一次，不再发下一手。
- 房主主动离开且仍有在线玩家时，在线接任者能继续操作房主能力；无在线候选者时由等待期内首位恢复者接任，不能随机指定离线玩家。其他人的本场不断开。
- 最后一人主动离开进入结束流程；所有人临时断线则等待 3 分钟，等待内恢复可继续，不能提前按“空房”删除。
- 全员断线计时与重启交叉时，保留正确截止时间；无人恢复到期后完成结束和结算。
- 在手间检查点提交前后、补充生效处、离开清算处和结束提交处强制终止进程，恢复结果均无重复记账、筹码丢失或半提交状态。
- 进行中强制重启后，回到最近完整结算；本手临时输赢全部回退，玩家看到回退说明，私有手牌不泄露。
- 恢复后的账本仍包含已离开者，最终合计为零；重复恢复和重复结束不生成第二份最终结算。

### 里程碑 4：30 天结算分享与全流程验收

**交付范围**：整场最终结算页、只读分享链接、从结束时起 30 天有效、过期状态，以及手机好友约局到最终分享的端到端验证。

**验收门槛**：

- 最终页同时列出在场与已离开者的补码次数、累计投入、最终归属和净盈亏，并可核对总和为零。
- 好友在独立浏览器打开链接可阅读结算，无需账号；链接只读，不能恢复身份或发出牌局操作。
- 检查分享接口、页面数据和链接，不含重连凭证、私有手牌等敏感信息。
- 在结束后 30 天边界验证可读/失效行为；访问、转发或重新复制不重置有效期。
- 2 人与 6 人完整路径均通过：邀请 → 加入 → 多手行动 → 中途加入 → 爆零补充 → 离开/重入 → 断线/刷新恢复 → 重启回退 → 房主结束 → 分享/到期。
