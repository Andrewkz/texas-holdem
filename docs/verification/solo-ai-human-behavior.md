# 单机 AI 行为与下注随机性验收

日期：2026-10-17。范围：单机六人桌的五名 AI；真人联机规则、服务端行动时限和底池归属规则不变。已于2026-10-17 23:58:11（Asia/Shanghai）发布，并通过最终构建包本地及公网连续多手浏览器验证。

## 行为变化

每张新桌给五名 AI 分配保守、偏跟注、激进、均衡、善变五种不同风格，并加入小幅个人差异。同一桌跨手保留风格；重新开桌或筹码耗尽后重开现金桌才重新分配。风格影响松紧程度、进攻和诈唬频率、下注尺寸偏好以及基础节奏，并不把某种手牌固定映射到一种行动。

行动概率结合自己的两张底牌、公共牌、真实跟注缺口、底池价格、剩余筹码风险、在手人数与公开位置。短码不足以正常跟注时仍保留完整跟注缺口，不再因缺少普通 call 动作而视为免费过牌，也不再无条件全压。AI 仅查询当前行动者自己的底牌，未读取其他玩家私牌。

可见牌力复用实际五至七张牌评估，区分顶对、中对、底对、超对和仅公共牌形成的对子或三条。四张同花、两头顺和卡顺只在翻牌或转牌且有私人贡献时计为听牌；河牌落空归零。私人强成牌与公共牌共享成牌分开处理：公共皇家同花顺不弃牌，也不因共享牌型优势主动大幅加注。所有分数都是有界启发式，不是校准胜率、GTO、求解器结果或已拟合的真人策略。

翻前使用多个开池、再加注档位；翻后使用四分之一、三分之一、半池、约三分之二、四分之三、一倍及超池等候选，再按风格小幅波动。金额受引擎最小加到和“本轮已投入＋剩余筹码”的真实上限约束，生成整数筹码；触及上限使用全压动作。随机源边界值不会生成越界或非有限下注金额。

基础思考时间为 0.35–1.8 秒，按公共决策压力、街次和个人节奏变化，不依赖自己的牌力或预选行动，避免固定时长直接泄露策略。界面仍按用户选择的动画速度缩放实际等待时间，因此墙钟时间并非始终落在该基础区间。返回首页会使旧会话失效并取消待执行工作，旧 AI 不会继续下注。

## Cocos 编译兼容问题与回归

实际旧构建包 `assets/main/index.js` SHA-256 为 `71af36c41e4e5477d3370313da9ca31a6a815a04fb420ad1e5bf510d266f1428`。浏览器多手验收发现座位余额 NaN；同一轮浏览器没有控制台异常或资源请求失败，说明仅检查页面错误不足以证明规则正确。

直接抽取旧包中的真实 `System.register` 模块执行，复现以下问题：Cocos loose spread 将 Set/Map 迭代器展开编译成 `[].concat(iterator)`。`SidePot` 得到 Set 对象而非金额层级，边池计算产生 NaN；`HandEvaluator` 的 Map entries/keys 没有展开，AA 被评为高牌、顺子无法正确识别；`AiHandStrength` 的公共牌 rank keys 同样受影响。

修复只把这三个算法模块的 Set/Map 迭代器展开改为 `Array.from`，保留原有数组展开和规则语义。`CocosIterableCompatibility.spec.ts` 使用已安装 Creator 的同款 Babel loose spread 插件编译并执行真实源码：先复现 3 个失败；修复 core 后再次观察顶/中/底对均为 0.64 的失败；修复 AI keys 后 4/4 通过。该工具链专项依赖本机 Creator，其他环境可通过 `COCOS_BABEL_MODULES` 指定引擎的 node_modules；本次完整 540 项执行中未跳过。

重建后真实模块探针确认 AA 为一对、主池/边池金额为 120/160、顶/中/底对为 0.64/0.50/0.38、共享皇家同花顺标记正确，未再以类型检查或源码测试代替构建包行为检查。
