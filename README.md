# Texas Hold'em

基于Cocos Creator 3.8.8的德州扑克游戏，支持单人与5名AI对战，以及2–6人好友联机。使用虚拟筹码，支持完整下注、边池、整场账本、爆零补码、重启检查点恢复与只读结算分享。

## 运行

1. 用 Cocos Creator 3.8.8 打开本目录。
2. 在 `assets/scenes/Game.scene` 打开 `Game` 场景，并将它设为构建的首场景。
3. 点击预览或运行。推荐使用 1280 × 720 横屏分辨率。

没有邀请或可恢复联机身份时，启动进入首页，可查看游戏规则或调整音效、动画速度和返回确认；有效邀请进入目标房间入口，有效原身份优先恢复。点击“单机游戏”才会创建单机牌局。设置保存在本机并在下次启动时恢复。

进入牌局后，轮到你时可点击底部的弃牌、过牌/跟注、自定义加注或全压按钮。五名 AI 分别有稳定的保守、偏跟注、激进、均衡、善变风格；同样的手牌会按价格、人数和位置混合行动，下注尺寸与思考节奏各有变化。基础思考时间为 0.35–1.8 秒，并随动画速度设置缩放；发牌、公共牌翻开和筹码移动仍播放动画。右上角“返回首页”可结束当前牌局；启用返回确认时会先显示确认弹层。

单机模式在玩家座位旁显示“胜出约 X% · 平局约 Y%”，仅用自己的两张底牌、已公开公共牌和仍在局中的对手人数，分批模拟 1000 次随机未知手牌。独赢与并列最好分开显示；公共牌和人数变化时刷新，同一信息保持稳定，弃牌、结算或返回时清除。该提示不读取 AI 底牌，也不调整洗牌或 AI 决策；未建模对手下注范围、未来弃牌或边池权益。

单机轮到玩家且动画完成后，头像显示 30 秒下注圆环，末 5 秒变红并按声音设置提醒。单机与联机的加注、全压弹窗同步显示真实剩余秒数和超时动作，末 5 秒突出显示；不会因打开弹窗或编辑金额重置。时间独立于动画速度，打开加注/全压确认或返回确认不重置，后台经过时间仍计入；超时优先自动过牌，否则弃牌，不自动跟注或全压。每次重新获得行动权开始新 30 秒，离开牌桌后取消待处理计时。

单机与联机牌桌显示独立文字徽标：青色“小盲 SB”、棕色“大盲 BB”和金色“庄家 D”；双人牌局庄家兼小盲时显示“庄家 / 小盲”。位置固定于本手开始时的参与者，弃牌、全压及结算期间保留并保持清晰，下一手随庄位正确轮转，跳过未参与者；联机重连按当前本手信息恢复，等待下一手加入者不会获得本手盲位。

牌桌物理顺时针顺序统一为“山雀 → Marco → Nova → 你 → 夜航 → Luna”。单机首手山雀庄家、Marco 小盲、Nova 大盲，你首先行动；翻牌后从庄家顺时针下一位仍可行动的玩家开始，下一手庄位也沿该方向轮转。联机仅将服务端既有参与顺序映射到本人的顺时针视角，本人保持底部；不重排服务端已有座位或持久记录。

首页“设置 → 盲注”或联机建房前的“建房盲注”可选 10/20、20/40、50/100、100/200，或自定义正整数（小盲 < 大盲 ≤ 1000，允许非1:2）。默认20/40，本机记住选择；单机新桌生效，联机只由创建者确定本场配置，加入者沿用房主数值，本场内固定。扣盲、最小加注、AI尺寸、HUD、大厅和重启恢复均使用该配置，初始筹码仍5000。

移动端默认直接横向展示整个游戏，不显示转屏提示或设置按钮：竖着拿手机时游戏页面自动横向铺开，横着拿时正常横向展示；PC保持原布局，窄PC窗口也不会被误判为移动端。移动端以同源横向游戏视口承载Canvas和全部原生弹窗/输入，浏览器统一映射触摸坐标，转屏保留同一个游戏实例、表单、房间与下注截止时间，父页不会重复启动引擎。

玩家下注状态采用独立高对比徽标：跟注为绿色、加注为金色、全压为暖橙色、过牌为蓝色、弃牌为灰色；弃牌徽标保持明亮，手牌继续淡出。桌面与手机尺寸的状态文字至少12CSSpx，桌面下注数字加粗并加底色，常规金额14CSSpx，长金额自适应完整显示。状态来自本轮动作与当前真实标志，换街/换手清理旧动作；联机恢复时仅有金额的玩家显示“已下注”，不推断其跟注或加注。

人物界面采用 Pen 生成的六张统一风格插画头像，姓名、精确筹码、行动状态分行；倒计时只描头像外圈并在底部显示数字，不遮住人物。长昵称按字符组省略，等候提示及结算仍使用完整名字。四个操作按钮名称与精确金额分两行，跟注、全压与余额不使用近似缩写；手机字号、按钮高度、短屏底池与下注数字位置按可用空间适配。

单机完成派彩动画后直接开始下一手，不自动弹出结算面板，也不额外停留。单机与联机均提供“上手结果”，按玩家汇总本手所有派彩并保留完整昵称，区分获得筹码与净变化；单机可核算本手净变化，联机不推算未知净值。历史面板在下一手或轮到本人行动时自动关闭，不延长服务器行动时间。

牌桌采用细腻低对比绒布、皮革色桌沿与细缝线；底池和顶部局数/盲注提亮，公共牌空槽轻量编号，隐藏重复的装饰牌堆；加注为主强调，全压为克制暖色。当前行动者筹码提亮、弃牌信息保留可读；这些为视觉变化，不改变座序、盲注或下注规则。

牌桌标明“总底池”包含已收底池与本轮下注；中央筹码另显示“已收”精确金额，避免重复相加。桌面筹码按同桌当前可见金额共用比例：最大堆为12个显示单位，100与200的显示量为1:2，已收底池与本轮下注一起比较。整单位显示为筹码层，小数余量用透明度和连续细量条表达，精确数字始终保留；比例只计已收底池和实际有座位的下注，不重复计入总底池。最多7堆×12图，逐次重用节点；此相对尺度会随同桌最大堆变化，并非固定筹码面额或PNG总体轮廓高度的精确倍数。

游戏提供按钮、卡牌、筹码和结算基础音效，不包含背景音乐。

选择“自定义加注”可直接输入总下注额、用 `−20 / +20` 调整，或选择最小、半池、满池、全压档位；确认前不会改变牌局。

## 联机对战

`server/` 是权威联机服务器（Node + ws）：建房、发牌、行动校验与结算都在服务端执行，手牌只发给本人。

本地运行：

```bash
pnpm install
cd server && pnpm install   # 生成 server/pnpm-lock.yaml（首次）
cd ..
pnpm --dir server dev       # 默认监听 ws://localhost:2567
```

客户端连接：首页 → 联机对战 → 填写昵称、服务器地址（本地开发填 `ws://localhost:2567`）→ 创建或加入房间。也可以用 URL 参数指定服务器，如 `?server=ws://localhost:2567`（优先级高于页面填写与本地存储）。

部署（Render 免费档）：

1. 推送本仓库后，在 Render 新建 Web Service，Root Directory 填 `server`。
2. Build Command：`pnpm install`；Start Command：`pnpm start`。
3. 部署后得到 `wss://<服务名>.onrender.com`，客户端服务器地址填它（GitHub Pages 的 HTTPS 页面只能用 `wss://`）。
4. 免费档空闲约 15 分钟休眠，首个连接冷启动约 30–60 秒，客户端会提示稍后重试。

游客使用稳定的本场身份和浏览器localStorage中的证明恢复，不按昵称恢复。主动离座保留证明，须明确重入取回原筹码，不重复发放5000。完整手检查点与控制意图持久保存，重启后未结手回退并显示说明。联机牌桌显示服务端30秒下注倒计时及进度条，最后5秒变红；刷新与重连不重置当前行动时间。到期可免费过牌则过牌，否则弃牌；全员断线180秒后按检查点结束。

联机相关测试在 `tests/net/`（协议校验、房间大厅、完整牌局、断线重连与超时、真实 WebSocket 集成）；服务器代码用 `pnpm run typecheck:server` 检查。

## 第一阶段运行说明

本节保留第一阶段历史行为；38/38任务按用户批准的浏览器验收标准完成，原v2发布见 [第一阶段发布记录](docs/verification/production-2026-10-17-phase1.md)。当前线上使用协议v4，身份和离座模型沿用下文v3说明。

构建标识与逐场景证据见 [第一阶段验收记录](docs/verification/friends-poker-phase-1.md)。按用户2026-10-17的最新要求，本阶段以实际编译包的浏览器流程及手机视口模拟验收；真实手机验证不再作为完成前置条件，报告仍明确模拟范围。

- 邀请入口使用同站路径的 `?room=AB23`，也保留手动输入四位房间码。房间码 trim/转大写后仅接受协议字符表，错误或冲突邀请参数显示失败，不自动恢复另一房间。
- 分享只包含房间码，不包含 token、昵称或已保存服务器。生成前核对当前实际后端与站点部署目标；自定义后端无法生成可移植邀请时明确提示。邀请弹窗始终提供“复制链接”，可选系统分享。邀请、本场结算和独立公开结算页均支持现代剪贴板及 HTTP 页面用户点击兼容复制；浏览器拒绝时选中完整链接并明确提示手动复制，不虚报成功。
- 有邀请时，以站点部署目标确定服务器，再匹配恢复凭证；旧自定义地址不能覆盖好友邀请。无邀请的普通入口保留 URL 参数、存储地址、同源 `/ws` 和本机默认的既有优先级。
- 刷新先尝试恢复同一 endpoint/房间/令牌的座位，恢复失败须明确选择重新加入；不按昵称恢复，不静默新增玩家或发放 5,000。取消恢复保留凭证，主动离房只清理匹配的凭证，防止删除其他标签页已替换的身份。
- 协议 v2：每条连接先完成双向 hello。旧版、缺少必需字段或握手失败会给出刷新/升级提示，握手前不发送恢复令牌。客户端与服务端必须配套发布，不能只替换其中一端。
- 服务端在首次确认一次断线时建立 180 秒保座期限；重复 close 不延期，到期即拒绝旧令牌，即使定时清理回调延迟。心跳确认半开连接需要额外时间，客户端重试预算不是服务端精确倒计时。行动超时仍为 30 秒，恢复不重置，能过牌则过牌，否则弃牌。
- 中途加入立即收到公共状态并显示等待下一手；每次推送按接收者过滤合法动作，未参与本手者无本人底牌。冻结实际发牌名单，包含盲注全压者，排除未发牌的零筹码座位；离席者本手身份与等待新玩家分开。
- 房主主动离开时优先移交在线玩家；无候选时由保座期内首位有效恢复者接任。人数不足回大厅不是整场结算。第一阶段不包含补码、整场账本、正式结束本场、全员断线后的持久结算、服务器重启恢复或 30 天分享。
- 手机横屏以 667×375、844×390 CSS 像素及安全区为布局检查基准，主要操作实际触摸高度至少 44 CSS px；桌面保留 1280×720 与 1440×900 回归。移动输入提供“收起键盘，继续操作”入口，保留输入内容后回到确认操作；本阶段在浏览器验证原生输入、缩小可视区域、旋转与模拟安全区、页面冻结/恢复和网络恢复。系统键盘、真实设备安全区和操作系统后台机制未在真机验证，不把浏览器模拟写成真机通过。

## 界面、下注与声音

2026-10-17按用户grill-me确认的7项设计实施，Pen源稿保存在`poker.pen`的11个Private Club画板。界面统一炭灰/深青/柔金；联机入口优先，当前玩家头像倒计时，底部四操作固定。加注使用原生数字输入、滑杆、快捷档的底部抽屉；全压有独立确认，取消不出牌，断线/换手/合法范围改变会关闭过期操作。

声音包含点击、发牌、筹码、过牌、弃牌、结算、本人回合及5秒提醒，无背景音乐/语音；过牌/弃牌无筹码音，多边池只响一次结算。设置有总静音、音量、独立行动提醒、动画速度、离开确认，兼容旧本机偏好；牌桌可一键静音。后台与尚未真实手势解锁时不积压提醒。设计与实现范围见[已确认设计](docs/superpowers/specs/2026-10-17-private-club-polish.md)。

透明筹码素材保存在`assets/resources/chips/`，由Pen生成单枚/小堆并抠图。玩家面前显示本轮下注，中央显示已收池筹码，底池总额不重复计算；结算清台，下注与派奖动画复用材质。图标堆叠用于表达规模，精确金额以数字为准。手机横屏与桌面均避免遮挡牌面、座位金额和操作栏。

## Ubuntu 服务器部署

## 结构

- `assets/scripts/core`：牌堆、牌型比较、边池及下注状态机。
- `assets/scripts/ai`：五名 AI 的合法行动策略。
- `assets/scripts/bootstrap/GameBootstrap.ts`：桌面横屏 UI、交互和动画，以及联机入口与牌桌接线。
- `assets/scripts/net`：协议类型、WebSocket 客户端（NetClient）、联机会话（OnlineSession）与凭证存取。
- `server/`：联机服务器（房间管理 + 权威牌局裁决）。
- `assets/scenes/Game.scene`：挂载 `GameBootstrap` 的运行场景。
